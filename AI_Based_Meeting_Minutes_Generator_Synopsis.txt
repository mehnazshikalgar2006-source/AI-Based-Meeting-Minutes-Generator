2. Introduction
Generative AI, powered by large language models (LLMs), has transformed how unstructured text is processed, summarized, and made actionable. One recurring administrative burden in academic and corporate settings is the manual creation of meeting minutes—reviewing lengthy discussions and converting them into concise, structured records. Traditional rule-based text-processing methods struggle to capture context, differentiate key decisions from casual discussion, or infer action items and owners. A GenAI-based approach is well suited here because LLMs can understand conversational context, summarize abstractively rather than just extracting sentences, and adapt to varied meeting formats without retraining. This project proposes a tool that takes a raw meeting transcript as input and automatically generates structured minutes, including a summary, key decisions, and action items, using an LLM-driven pipeline enhanced with Retrieval-Augmented Generation (RAG) for searching past meeting records.
3. Problem Statement
Manually preparing meeting minutes is time-consuming, inconsistent across note-takers, and prone to missed action items or decisions. There is no easy way to search across the accumulated history of past meetings for specific discussions or commitments. This project aims to automatically generate accurate, structured meeting minutes from transcripts and enables semantic search across historical meeting records using a GenAI-based pipeline.
4. Objectives
To design and develop a meeting-minutes generation tool using an LLM (GenAI model) for abstractive summarization.
To enable automatic extraction of key decisions, discussion points, and action items with owners and deadlines.
To evaluate the tool's performance using accuracy of extracted action items and summary relevance, benchmarked against manually prepared minutes.
To implement a Retrieval-Augmented Generation (RAG) layer for semantic search across past meeting records.
To provide an accessible web-based user interface for uploading transcripts and viewing/exporting generated minutes.
5. Scope of the Project
The project will cover summarization and structured extraction from text transcripts of single meetings, along with semantic search across a growing archive of processed meetings. Audio input will be supported via speech-to-text conversion as an optional extension. The tool targets students, faculty, and small teams who need a lightweight way to document and search meeting outcomes. It will not cover real-time live transcription during an ongoing meeting or integration with enterprise calendar/task systems in the initial version—these are noted under Future Scope.

7. Proposed System / Methodology
The tool accepts a meeting transcript as input, processes it through preprocessing and prompt-based LLM summarization, and produces structured minutes as output. Past meetings are embedded and stored in a vector database, enabling later semantic search via a RAG pipeline.
User Input: Upload of transcript text (or audio, converted via speech-to-text).
Pre-processing: Cleaning, segmenting, and optionally identifying speaker turns.
GenAI Model / API Processing: LLM prompted to generate a summary, decisions list, and action items with owners/deadlines.
Post-processing: Formatting the structured output and validating extracted action items.
Retrieval Layer (RAG): Storing meeting embeddings and enabling natural-language search across past minutes.
Output Delivery: Minutes displayed on a web UI and exportable as PDF/Word.

11. Applications / Real-World Relevance
This tool can be applied in academic institutions for documenting committee or project meetings, in corporate settings for tracking decisions and follow-up tasks across teams, and in legal or consulting firms for summarizing client consultations and discussions into structured, reviewable records.
12. Ethical Considerations & Limitations
Meeting transcripts may contain sensitive or confidential information, so data handling must ensure privacy and restricted access to stored records. LLM-generated summaries can occasionally misrepresent statements or omit nuance (hallucination), so generated minutes should be reviewed before being treated as an official record. The system's accuracy is also dependent on transcript quality, particularly when derived from noisy audio via speech-to-text.
