2. Functional Requirements Document
The functional requirements define what the proposed system should do. They are derived from the synopsis, which describes transcript input, preprocessing, LLM summarization, structured extraction, RAG-based search, web UI, and PDF/Word output.
Requirement
Description
FR-01 – Transcript Input
The system shall accept a meeting transcript as input. Audio input may be supported as an optional extension through speech-to-text.
FR-02 – Pre-processing
The system shall clean and segment transcript text and may identify speaker turns.
FR-03 – AI Summarization
The system shall use an LLM/GenAI model to generate an abstractive meeting summary.
FR-04 – Discussion Points
The system shall extract important discussion points from the transcript.
FR-05 – Decisions
The system shall extract key decisions made during the meeting.
FR-06 – Action Items
The system shall extract action items and identify owners and deadlines when available.
FR-07 – Post-processing
The system shall format the generated information into structured meeting minutes and validate extracted action items.
FR-08 – Meeting Storage
The system shall store processed meeting records for later retrieval.
FR-09 – Semantic Search
The system shall support natural-language search across previous meeting records.
FR-10 – RAG
The system shall use a RAG layer with meeting embeddings and a vector database for semantic retrieval.
FR-11 – Web Interface
The system shall provide a web-based interface for uploading transcripts and viewing generated minutes.
FR-12 – Export
The system shall allow generated minutes to be exported as PDF/Word.
FR-13 – Review
Generated minutes should be reviewed before being treated as an official record.

9. Security, Privacy and Limitations
Meeting transcripts may contain sensitive or confidential information; data handling should ensure privacy and restricted access.
LLM-generated summaries can misrepresent statements or omit nuance, so generated minutes should be reviewed before official use.
System accuracy depends on transcript quality, especially when audio is converted through speech-to-text.
Real-time live transcription and enterprise calendar/task integration are outside the initial version.
10. Expected Technical Result
A working prototype that converts meeting transcripts into structured minutes.
Demonstrated functionality using sample transcripts and generated outputs.
Performance evaluation covering summary relevance and action-item extraction accuracy.
Semantic search across past meeting records using RAG.
